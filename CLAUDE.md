# STEEL development context

STEEL is a layer on top of OpenJarvis, imported from `~/.openjarvis/.venv` and pinned to commit `108d257188cbad85f2e50209d9a61669ea4dec33` (`steel/pin.py`). Never edit the OpenJarvis source at `~/.openjarvis/src`. Import its shared core (registry, events, types); do not copy it. Any ported file needs a header and a row in docs/PROVENANCE.md.

Implemented (Phases 1, 1b, 2a, 2b, 2c, 3, 4, 5a, 5b, 5b-2, 5b-3 and 5c): `steel chat` with persistent OpenJarvis memory read from the user's messages only, `SteelFactStore` (forget-by-id, near-duplicate guard, time-bound facts routed to 7-day notes), `steel remember`, list/forget/wipe across all memory stores. Nothing is registered with OpenJarvis and the chat model cannot call a tool: **never** parse model output (or a tool result, a stored text or a voice transcript) for commands, tool calls or JSON actions. `steel/security/` holds `SteelPolicy` (deny by default, adapted from OpenJarvis `capabilities.py`; the only grantable wildcard is `memory:read:*`; sensor and `audio:play` grants must name one exact tool) and `build_executor`, the **only** place STEEL may construct a `ToolExecutor` (a test enforces it). `steel/tools/` holds three read-only memory tools, `memory_search_facts`, `memory_search_notes` (the owner's notes) and `memory_search_room` (room notes, `memory:read:room`, never covered by `memory:read:*`), one capability each, built only by `get_memory_tools(home)` and run only by `steel tool call` and the owner's typed slash commands (no model). Never write a tool that writes, and never add a `source` switch that lets one capability read two stores. **Voice (Phase 2c, docs/VOICE.md):** `steel/voice/` and `steel/tools/microphone.py` give push-to-talk input only. The push-to-talk microphone may be opened only by `steel.voice.recorder.record`, which prints the REC line first and passes the proof to the source (the always-on one only by `steel.jarvis.listen`, see Jarvis below); the tool `microphone_listen` declares only `sensor:microphone`, needs the consent file (`steel voice consent`) and the owner's hand-written grant, and returns transcript text, never audio. Audio stays in RAM, never in a file. **Never** import `openjarvis.speech` or `sounddevice`, call `get_speech_backend`/`get_tts_backend`, import `onnxruntime` or anything that loads it without `steel.offline.telemetry_off()` first (onnxruntime 1.31 sends Microsoft telemetry otherwise), add a cloud speech service, or a wake word or any always-on listening outside the one design the owner approved (**docs/JARVIS.md**, the `steel jarvis` loop, below), and never let `pytest` open a real microphone or speaker (fakes only; `scripts/voice_check.py` is the owner's live check and must not be run by an assistant). **Jarvis (Phase 5c, docs/JARVIS.md):** the owner lifted the wake-word rule on 2026-10-25 for that design only, and only while it meets every docs/VOICE.md section 7 requirement (if one cannot be met, stop and tell the owner; never weaken it). `steel/jarvis/` and `steel jarvis check|consent|revoke|stop` (the loop: `steel jarvis`); implemented and tested with fakes, not yet run live by the owner. **Never** a background service, daemon, start at login, or listening without the loop running in the foreground of a terminal the owner started (checked at start and while listening). The always-on microphone may be opened only by `steel.jarvis.listen.WakeListen` (tool `wake_listen`, built only by `steel.tools.get_wake_tool`, run only through `build_executor` as agent `jarvis`), after its own consent file (`steel jarvis consent`; the push-to-talk consent does not count), the models' pinned SHA-256 and the `ListeningShown` proof that only `Indicators.show_listening` makes after the terminal line is written AND the guard (`python -I -m steel.jarvis.guard`, its own process and session) answered `SHOWN` with its window mapped; it declares only `sensor:microphone_always_on` (a sensor: exact tool name, never a wildcard) and returns a status and a score, never audio or text. Every `arecord` runs through `setpriv --pdeathsig KILL`; the guard kills any microphone running without the window, and its watchdog kills the microphone and the loop when the frame loop's heartbeat stops; `steel jarvis stop` (pidfile with start times) needs nothing from the loop. Frames go only to the wake engine's fixed RAM buffers (110 ms of raw audio), zeroed after every listening; the request is a separate recording after the wake word (`microphone_listen`, voice consent and its own grant for `jarvis`), shown with a countdown before it is sent; wake transcripts never reach the fact extractor unless `--remember-voice`; nothing spoken is ever run (no slash command, camera or tool by voice); the microphone stays closed until the player has exited plus 0.5 s. Session, idle and wake-rate limits (`STEEL_JARVIS_*`, validated). The wake-word engine is STEEL's own port of openWakeWord (Apache-2.0, docs/PROVENANCE.md) on onnxruntime, imported only after `telemetry_off()` (`tests/test_telemetry_guard.py` checks every loader); never import the `openwakeword` package. The model files are **CC BY-NC-SA 4.0, non-commercial**, downloaded only by `scripts/wake_setup.py` and pinned by SHA-256 (trust on first use; docs/JARVIS.md 1.1). `scripts/jarvis_check.py` is the owner's live check and must not be run by an assistant; `scripts/wake_bench.py` measures the engine on synthetic audio only, by hand, never in pytest. Never let `pytest` open a real microphone, speaker, window or model (stand-in processes only; the real guard only with no display). **Vision (Phase 3, docs/VISION.md):** `steel/vision/` and `steel/tools/camera.py` give ONE picture per command, never video. The camera may be opened only by `steel.vision.capture.capture_one`, which prints the CAMERA OPEN line first and passes the proof to the source, after the owner's Enter key (`steel/vision/startkey.py`; in chat the typed `/look`); a black picture is retried at most once, with its own CAMERA OPEN line; the tool `camera_look` declares only `sensor:camera`, needs its own consent file (`steel vision consent`, independent of the voice one) and the owner's hand-written grant for agent `eyes`, and returns text only (first line: the description is data, not instructions), never the picture. The picture stays in RAM, is downscaled to at most 448 px and never written to a file. The picture goes only to a loopback Ollama through `OllamaEngine` (never `get_engine`, never a cloud service, never an `*_API_KEY`). **Never** add video, a loop, a timer, motion detection, face recognition or identification of people, never write a picture or temporary file, never feed camera text to a model that can call tools, and never let `pytest` open a real camera (fakes only; `scripts/vision_check.py` is the owner's live check and must not be run by an assistant). **Slash commands (Phase 4, docs/INJECTION.md):** `steel/slash.py` runs `/search`, `/notes`, `/room`, `/look` only for a line the owner TYPED, as agent `chat` through `build_executor`, with a per-session cap and a sensor gap. Every result goes through `steel.tooldata.prepare` (strip escapes, redact, cap, injection scan), is shown first, and is added to the chat only on Enter and only if not flagged, as a wrapped data message in RAM via `ChatSession.add_tool_data`. Tool output must **never** reach the fact extractor or any memory write, and one typed line runs at most one tool (no chaining). Model-initiated tool calls are NOT IMPLEMENTED; do not add them without everything in docs/INJECTION.md section 4. A new tool must declare its capabilities (and `path_params` if it touches files), and needs a reviewed grant in the policy before it can run; see docs/POLICY.md, including what the policy does not cover. **Spoken replies (Phase 5a, docs/SPEAK.md):** `steel/speak/` and `steel/tools/speak.py`. Opt-in per session (`--speak`), never default. The tool `speak` declares only `audio:play` (not a sensor, exact tool name required), runs only through `build_executor` as agent `voice`, takes the assistant's reply only and returns no text. **Never** pass it a tool-data block, a room note, camera text or a transcript; `steel.speak.text.prepare_speech` also refuses markers, flagged or unredactable text, strips markdown/links/code and caps the length. The engine is Piper (GPL-3.0-or-later): **never import `piper`, its onnxruntime or espeak-ng into STEEL's process**, and never copy its code; it runs only as a separate program via `steel.speak.synth.PiperEngine` (`unshare --net`, text on stdin only, never on the command line or in the environment, minimal environment with `ORT_DISABLE_TELEMETRY=1`; no `unshare`, no engine). The speaker may be opened only by `steel.speak.playback.play`, which prints the SPEAKING line first and passes the proof to `aplay` (raw PCM on a pipe). No audio or temporary file, no network at run time, never speak while the microphone is open, and never let `pytest` start the engine or a player (fakes only; `scripts/speak_check.py` is the owner's live check and must not be run by an assistant). Downloads happen only in `scripts/speak_setup.py`, pinned by SHA-256. **Latency (Phase 5b, docs/LATENCY.md):** the chat **never streams** (`GuardrailsEngine.stream` does not redact the output; keep `generate`). `steel/warm.py`: the warm-up (Phase 5b-2) sends the system prompt and memory a real first turn would send, built by `ChatSession.build_messages`, plus the fixed word `ready` as the only user turn (never a message of the owner's), with one token to generate, in a background thread; memory reaches only a loopback Ollama through the same guardrails, exactly as in a normal turn. It, `STEEL_OLLAMA_KEEP_ALIVE` (1s to 24h) and `STEEL_OLLAMA_NUM_CTX` (2048 to 32768, default 4096) apply only to an `OllamaEngine` on a loopback host, through STEEL's own httpx transport (`trust_env=False`), which sets `options.num_ctx` on EVERY chat/generate request (chat, warm-up, extractor; vision reads the same setting) because Ollama reloads a model when the context differs; never edit OpenJarvis to do it. `steel/context.py` cuts the oldest history so the prompt fits in `num_ctx` minus 1024. The base prompt has a token budget (`BASE_PROMPT_TOKEN_BUDGET`, tested) and every safety statement in it is pinned by a test; the warm-up's outcome (`WarmUp`) is printed only by the chat loop between turns, never from its own thread, and carries reason codes, never text. `--timings` prints numbers only and stores nothing. The engine may be started early (`PiperEngine.prepare`, from the chat's main thread, only if the read-only grant preview allows it, before the model is asked); the message only picks the voice and never reaches the engine; since Phase 5b-2 a stock-CLI engine stays loaded and since Phase 5b-3 the engines of the last `STEEL_SPEAK_KEEP_VOICES` voices (1 to 3, default 2; LRU eviction; `STEEL_SPEAK_VOICE_IDLE_MINUTES` 5 to 240, default 30) stay loaded, an interrupt replacing only the engine that was speaking; `engine: warm` describes the engine's state (served a reply or started 6 s earlier), never the speed of its first audio; each reply is one stdin line and ends by an idle gap (`STEEL_SPEAK_IDLE_END_SECONDS`, 0.5 to 5, default 1.5, longer for a long sentence); an interrupted, silent or dead engine is replaced by a clean one (never drained), a language change stops the other voice's engine, audio found unread at the next reply replaces the engine, and the process-per-reply way (end of file) remains the fallback and `STEEL_SPEAK_PERSISTENT=0`. It runs under `setpriv --pdeathsig KILL` and the chat must `close()` it on every exit path. Never write a program of STEEL's own that imports Piper to mark the end of a reply. `scripts/latency_check.py` is the owner's live script and must not be run by an assistant. See README.md for the capability table.

Use Python 3.11–3.13. Runtime depends on OpenJarvis only. Type-hint runtime code, format and lint with Ruff, type-check `steel` with mypy, and run `pytest` (it must never call the live model) before commits. **Runaway tests:** every test phase has a time limit (`tests/conftest.py`, SIGALRM, `STEEL_TEST_TIMEOUT` seconds, default 60, 1 to 3600, anything else is a usage error; `tests/test_test_timeout.py` tests it); run the suite under `timeout 600` and single tests under `timeout 60`, never in a retry loop; every fake that a loop polls, reads or sleeps on must raise after a maximum number of calls, and a fake clock must advance when it is waited on, so no test can spin forever (one did on 2026-10-25, grew about 60 MiB a second and froze the computer). `scripts/quality_check.py` is the only live-model check and uses a scratch directory. Keep examples synthetic and never commit local databases, credentials or recordings.

Do not describe planned capabilities as implemented, claim GDPR compliance or add external actions without a reviewed consent and authorization design. Keep README, SECURITY.md, ARCHITECTURE.md and the docs (POLICY, VOICE, VISION, INJECTION, PROVENANCE, ROADMAP) synchronized with what the code does. Record AI-assisted implementation honestly.

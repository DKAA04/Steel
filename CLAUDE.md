# STEEL development context

STEEL is a layer on top of OpenJarvis, imported from `~/.openjarvis/.venv` and pinned to commit `108d257188cbad85f2e50209d9a61669ea4dec33` (`steel/pin.py`). Never edit the OpenJarvis source at `~/.openjarvis/src`. Import its shared core (registry, events, types); do not copy it. Any ported file needs a header and a row in docs/PROVENANCE.md.

Implemented (Phases 1, 1b, 2a, 2b and 2c): `steel chat` with persistent OpenJarvis memory read from the user's messages only, `SteelFactStore` (forget-by-id, near-duplicate guard, time-bound facts routed to 7-day notes), `steel remember`, list/forget/wipe across all memory stores. Nothing is registered with OpenJarvis and the chat model cannot call a tool. `steel/security/` holds `SteelPolicy` (deny by default, adapted from OpenJarvis `capabilities.py`; the only grantable wildcard is `memory:read:*`) and `build_executor`, the **only** place STEEL may construct a `ToolExecutor` (a test enforces it). `steel/tools/` holds the first two tools, `memory_search_facts` and `memory_search_notes` (read only, one capability each), built only by `get_memory_tools(home)` and run only by `steel tool call` (no model). Never write a tool that writes, and never add a `source` switch that lets one capability read two stores. **Voice (Phase 2c, docs/VOICE.md):** `steel/voice/` and `steel/tools/microphone.py` give push-to-talk input only. The microphone may be opened only by `steel.voice.recorder.record`, which prints the REC line first and passes the proof to the source; the tool `microphone_listen` declares only `sensor:microphone`, needs the consent file (`steel voice consent`) and the owner's hand-written grant, and returns transcript text, never audio. Audio stays in RAM, never in a file. **Never** import `openjarvis.speech` or `sounddevice`, call `get_speech_backend`/`get_tts_backend`, add a cloud speech service, a wake word or any always-on listening, and never let `pytest` open a real microphone or speaker (fakes only; `scripts/voice_check.py` is the owner's live check and must not be run by an assistant). A new tool must declare its capabilities (and `path_params` if it touches files), and needs a reviewed grant in the policy before it can run; see docs/POLICY.md, including what the policy does not cover. See README.md for the capability table.

Use Python 3.11–3.13. Runtime depends on OpenJarvis only. Type-hint runtime code, format and lint with Ruff, type-check `steel` with mypy, and run `pytest` (it must never call the live model) before commits. `scripts/quality_check.py` is the only live-model check and uses a scratch directory. Keep examples synthetic and never commit local databases, credentials or recordings.

Do not describe planned capabilities as implemented, claim GDPR compliance or add external actions without a reviewed consent and authorization design. Keep README, SECURITY.md and ARCHITECTURE.md synchronized with what the code does. Record AI-assisted implementation honestly.

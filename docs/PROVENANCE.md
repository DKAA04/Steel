# Provenance

STEEL imports OpenJarvis (Apache-2.0, https://github.com/open-jarvis/OpenJarvis) from the pinned install at commit `108d257188cbad85f2e50209d9a61669ea4dec33`. Imported code is not copied into this repository and is not modified.

Any file ported (copied and adapted) from OpenJarvis must start with a header giving its source path, the commit, the Apache-2.0 license and what changed. It must also get a row here.

| STEEL file | OpenJarvis source path | Commit | What changed |
| --- | --- | --- | --- |
| `steel/security/policy.py` | `src/openjarvis/security/capabilities.py` (`CapabilityPolicy._check_python`, `AgentPolicy`, `CapabilityGrant`, and the policy-file validation in `_load_file`) | `108d257188cbad85f2e50209d9a61669ea4dec33` | Pure Python only (no Rust). **Inverted from open-by-default to deny-by-default**: an unknown agent, an unmatched capability or any error is a deny, and the `_default` fallback agent is removed. Fixed capability vocabulary; exact matching instead of `fnmatch`; path grants matched on resolved path components; sensors never covered by a wildcard; every decision written to a names-only audit log; strict policy-file validation. Details: docs/POLICY.md |

## Code ported from other projects

| STEEL file | Source | Version | Licence | What changed |
| --- | --- | --- | --- | --- |
| `steel/jarvis/wakeword.py` | openWakeWord, https://github.com/dscripka/openWakeWord: `openwakeword/utils.py` (class `AudioFeatures`, the streaming feature path) and `openwakeword/model.py` (`Model.predict`) | 0.6.0, tag `v0.6.0` = commit `c8ef6912c5feccf1037b852d9bc6c7ed644135ba` (the two files were read at that commit on 2026-10-26; when the port was first written on 2026-10-25 only the version number was recorded) | Apache-2.0, Copyright 2022 David Scripka | Only the streaming path for one model; 80 ms frames only; much smaller fixed buffers (110 ms of raw audio instead of 10 s, docs/JARVIS.md section 2); the buffers can be zeroed (`wipe`, `reset`); the three ONNX sessions are injectable for tests; onnxruntime is imported only after `telemetry_off()`; no downloader and no `openwakeword` package. The file header says the same. **Deviations that remain** (see the next paragraph): the initial feature history comes from seeded noise (`default_rng(0)`), not unseeded noise; the 16 embeddings are fixed, not read from the model; no Speex noise suppression and no voice-activity detection (both are off by default upstream). |

**What was checked and what was not.** The port was first written with Claude Code (Claude Opus 5.5) on 2026-10-25. On 2026-10-26 the assistant fetched exactly two upstream files as text (`openwakeword/utils.py` and `openwakeword/model.py` at commit `c8ef6912c5feccf1037b852d9bc6c7ed644135ba`, the commit the tag `v0.6.0` points to; never imported, installed or run; deleted afterwards; no line of them is in this repository) and compared them with `steel/jarvis/wakeword.py` for: the sample rate and frame size (16 kHz, 1,280 samples), the mel model's input and the `x/10 + 2` transform, the raw context given to the mel model, the 76-frame window with stride 8 and its initial buffer of ones, the embedding model's input shape and name, the 16 embeddings given to the classifier, the first 5 predictions forced to 0, and the handling of the model's output. All matched except one thing that could change what the model hears: after a reset, upstream computes the first frame's mel spectrogram over the 1,280 real samples only (its raw buffer is cleared), while the first version of the port used 480 zero samples before them. **That was fixed on 2026-10-26** (tests: `WakeEngineTest.test_the_first_frame_after_a_reset_has_no_zero_context_like_upstream`, `test_the_second_frame_gets_its_context_from_the_real_first_frame`, `test_buffers_stay_at_their_maximum_after_the_shorter_first_input`). The deviations above remain and are harmless by design: seeded instead of unseeded noise for the initial history, the 16 fixed, and two upstream options that are off by default. Not compared: anything else in the two files (the other framework branches, batch and training helpers, custom verifier models). The comparison was made by the assistant reading the text, not by an independent human reviewer. On 2026-10-26 the real models ran on synthetic audio (docs/JARVIS.md section 1.2: silence 0.0000, noise at most 0.2508), **and whether the port detects a real "hey jarvis" is measured only by the owner's live check** (`scripts/jarvis_check.py`). The model files are not code and are not in this repository: they are downloaded by `scripts/wake_setup.py` and are **CC BY-NC-SA 4.0, non-commercial** (docs/JARVIS.md section 15, NOTICE section 4).

`steel/security/executor.py` subclasses `openjarvis.tools._stubs.ToolExecutor` and contains no copied code. `steel/tools/microphone.py` subclasses `openjarvis.tools._stubs.BaseTool` and contains no copied code.

**Voice (Phase 2c) copies nothing from OpenJarvis and has no row above.** `steel/voice/` deliberately does not import `openjarvis.speech` (see docs/VOICE.md section 2: its discovery can choose a cloud backend, its Faster-Whisper backend writes the audio to a temp file and takes a model name that may be downloaded, and importing the package loads the cloud backends too). It reuses OpenJarvis only for the tool base classes and `ToolExecutor`. Third-party components it uses, with the licenses read from the installed package metadata and the Hugging Face model cards on 2026-10-24: `faster-whisper` 1.2.1 (MIT), `ctranslate2` 4.8.3 (MIT), `onnxruntime` 1.31.0 (MIT), `av` 19.0.2 (BSD-3-Clause), `tokenizers` 0.23.3 (Apache-2.0 classifier), `soundfile` 0.14.0 (BSD-3-Clause) and `sounddevice` 0.5.6 (MIT) (the last two arrive with the `[speech]` extra and are not imported by STEEL); models `Systran/faster-whisper-small` and `Systran/faster-whisper-base` (MIT), revisions and checksums in docs/VOICE.md section 3. `arecord` (alsa-utils) is run as a separate program. `steel/facts.py` subclasses `openjarvis.memory.store.LocalFactStore` and uses its private members. It contains no copied code.

**Vision (Phase 3) copies nothing from OpenJarvis and has no row above.** `steel/vision/` and `steel/tools/camera.py` subclass `openjarvis.tools._stubs.BaseTool` and import, by name, `OllamaEngine`, `Message`/`Role`, `GuardrailsEngine` with `SecretScanner`/`PIIScanner`, and `InjectionScanner`. They do not use `get_engine` (it may pick another engine, and a picture must go only to a local Ollama) and import no OpenJarvis speech, image-generation or cloud code. OpenJarvis offers no camera capture and no vision tool (`tools/image_tool.py` is DALL-E image *generation*); see docs/VISION.md section 2.

**Slash commands (Phase 4) copy nothing from OpenJarvis and have no row above.** `steel/slash.py`, `steel/tooldata.py` and `steel/meminfo.py` are new code. They import `ToolCall`, `BaseTool`, `SecretScanner`, `PIIScanner` and `InjectionScanner` by name and run tools through the stock `ToolExecutor` built by `build_executor`. `steel/meminfo.py` reads `/proc/meminfo` with the standard library only.

**Spoken replies (Phase 5a) copy nothing from OpenJarvis or from Piper and have no row above.** `steel/speak/` and `steel/tools/speak.py` are new code; the tool subclasses `openjarvis.tools._stubs.BaseTool`, and the text rules reuse STEEL's own `steel.tooldata` (which calls the OpenJarvis Secret, PII and injection scanners by import). **Piper** (`piper-tts` 1.8.0, GPL-3.0-or-later, https://github.com/OHF-Voice/piper1-gpl, which embeds espeak-ng, also GPL-3.0-or-later) is **not imported, copied or redistributed**: STEEL starts it as a separate program from its own virtual environment and talks to it only through pipes (docs/SPEAK.md section 4). The command-line options STEEL passes (`-m`, `--output-raw`) were read from Piper's `__main__.py` to call it correctly; no line of it is in this repository. The voices (`rhasspy/piper-voices` at revision `5041a7a49ae5b3a0f30e6837769eb03fdbb231bd`) are downloaded onto the owner's machine by `scripts/speak_setup.py` and are not in this repository; their licences are those of their recordings (docs/SPEAK.md section 3). `scripts/piper-requirements.txt` is a lock file generated with `uv pip compile`, listing names, versions and published SHA-256 values only. OpenJarvis' own `openjarvis.speech` text-to-speech backends (Kokoro, OpenAI, Cartesia) are not used. The Phase 5a design, code, tests and measurements were written with Claude Code (Claude Opus 5.5); they are checked by the tests in docs/SPEAK.md section 10, and the owner reported on 2026-10-25 that the live check works.

**The latency work (Phase 5b) copies nothing from OpenJarvis or from Piper and has no row above.** `steel/timings.py` and `steel/warm.py` are new code. `steel/warm.py` imports `OllamaEngine`, `Message` and `Role` and, for a local Ollama with `STEEL_OLLAMA_KEEP_ALIVE` set, replaces the engine's private `_client` with an `httpx.Client` of STEEL's own; it reads the private `_host`, `_timeout` and `GuardrailsEngine._engine`, so it relies on the pinned commit like `SteelFactStore` does. Since Phase 5b-2 the replaced `_client` is installed for every local `OllamaEngine` (it sets `options.num_ctx` on each request; why 16384 appeared was read in `engine/ollama.py`, `_default_num_ctx`), and `steel/context.py` is new code that uses only `Message` and `Role`. `steel/speak/synth.py` still runs Piper only as a separate program; how the stock CLI behaves with several stdin lines was measured by running the installed engine into memory (docs/SPEAK.md section 2.3); nothing of Piper is copied. How OpenJarvis streams and redacts was read in `engine/ollama.py` and `security/guardrails.py` at the pinned commit; nothing was copied. How the Piper CLI handles several stdin lines, and that it writes each sentence as it is made, was read in Piper 1.8.0's `__main__.py` and `voice.py` and checked by running the installed engine into memory; no line of it is in this repository, and STEEL still only runs it as a separate program. `LICENSE` is the Apache-2.0 text from https://www.apache.org/licenses/LICENSE-2.0.txt (taken from a copy shipped by `sniffio` in the OpenJarvis environment, with the same SHA-256 as apache.org's file) after one copyright line. The M-AILABS notice in `NOTICE` is quoted from `github.com/i-celeste-aurora/m-ailabs-dataset` (README.md, fetched 2026-10-25). Written with Claude Code (Claude Opus 5.5); not yet reviewed or measured live by the owner.

# Roadmap

1. Done: offline note store with expiry and regression tests.
2. Done (Phase 1): packaging on a pinned OpenJarvis commit, `steel chat` with OpenJarvis automatic memory, forget-by-id and wipe across all memory stores, private file permissions. No tools.
3. Done (Phase 1b): user-only extraction, near-duplicate guard, related facts on forget, 7-day notes for time-bound facts, `steel remember`. Open: forget still blocks only the same wording; named people: decided to stay as stored, revisited when a tool can read memory (docs/MEMORY_QUALITY.md).
4. Done (Phase 2a): `SteelPolicy`, `build_executor`, the names-only decision log, `steel policy show`; designed (docs/POLICY.md) and tested **before** any tool existed.
4b. Done (Phase 2b): policy hardening (one grantable wildcard, `grant_moved`, log rotation, a test that `ToolExecutor.execute` is the only way to run a tool) and the first tools, `memory_search_facts` and `memory_search_notes` (read only), run from `steel tool call` with no model. Open: legacy names (POLICY.md section 6); per-person handling of memory, now that a tool can read facts (docs/MEMORY_QUALITY.md).
5. Voice and vision: define consent, visible recording indicators and retention before attaching sensors. Room observations build on the expiring note store.
5a. Done (Phase 2c): push-to-talk voice input, fully local: consent file, visible REC line, `microphone_listen` tool behind `sensor:microphone`, `steel voice check|consent|revoke|listen`, `steel chat --voice [--speak]`, `scripts/voice_check.py`. Designed first (docs/VOICE.md), tested with fake audio. Live-checked by the owner on the real microphone; since then Whisper gets a vocabulary hint (`STEEL_VOICE_HINT`). **Open:** Spanish and Italian accuracy (unmeasured), the effect of the hint (unmeasured), `espeak-ng` (not installed; fake-tested only), whether speaking needs a capability, a lock for several processes. **Not implemented, by design: wake word and always-on listening** (docs/VOICE.md section 7).
5b. Done (Phase 3): one camera snapshot on demand, fully local: consent file, visible CAMERA OPEN line, `camera_look` tool behind `sensor:camera`, `steel vision check|consent|revoke`, `steel look [--save]`, `scripts/vision_check.py`. Designed first (docs/VISION.md), tested with a fake camera and a fake vision model. Live-checked by the owner on the real camera; since then the default model is `qwen3.5:2b` (about 25 s a look; `qwen2.5vl:3b` about 100 s). After the live check: a 20-frame warm-up and one retry for a black picture, and `steel look` waits for Enter. **Open:** how well either installed vision model describes a real room (not measured by a test). **Not implemented, by design: continuous video, always-on watching, motion detection, recognising or identifying people** (docs/VISION.md section 7).
5c. Done (Phase 4): slash commands in `steel chat` (`/search`, `/notes`, `/room`, `/look`), typed by the owner, run as agent `chat` through the policy; results are shown first and added to the conversation only on Enter, as data that never reaches memory; a separate `memory:read:room` capability and `memory_search_room` tool; `steel doctor` warns about memory pressure. Threat model and rules written first (docs/INJECTION.md). **The model still cannot run any tool.** Since Phase 5a room notes are not in the chat prompt (`/room` fetches them on demand). **Open:** a measured injection test suite against the real local model; per-person memory handling. **Not implemented, by design: model-initiated tool calls** (docs/INJECTION.md section 4 lists what must be true first).
6. Mobile/API: authentication and authorization must come before any remote command interface.

These are planned milestones with no promised dates. The security module will be limited to owned or explicitly authorized environments.

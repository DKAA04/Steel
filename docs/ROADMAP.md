# Roadmap

1. Done: offline note store with expiry and regression tests.
2. Done (Phase 1): packaging on a pinned OpenJarvis commit, `steel chat` with OpenJarvis automatic memory, forget-by-id and wipe across all memory stores, private file permissions. No tools.
3. Done (Phase 1b): user-only extraction, near-duplicate guard, related facts on forget, 7-day notes for time-bound facts, `steel remember`. Open: forget still blocks only the same wording; named people: decided to stay as stored, revisited when a tool can read memory (docs/MEMORY_QUALITY.md).
4. Done (Phase 2a): `SteelPolicy`, `build_executor`, the names-only decision log, `steel policy show`; designed (docs/POLICY.md) and tested **before** any tool existed.
4b. Done (Phase 2b): policy hardening (one grantable wildcard, `grant_moved`, log rotation, a test that `ToolExecutor.execute` is the only way to run a tool) and the first tools, `memory_search_facts` and `memory_search_notes` (read only), run from `steel tool call` with no model. Open: legacy names (POLICY.md section 6); per-person handling of memory, now that a tool can read facts (docs/MEMORY_QUALITY.md).
5. Voice and vision: define consent, visible recording indicators and retention before attaching sensors. Room observations build on the expiring note store.
5a. Done (Phase 2c): push-to-talk voice input, fully local: consent file, visible REC line, `microphone_listen` tool behind `sensor:microphone`, `steel voice check|consent|revoke|listen`, `steel chat --voice`, `scripts/voice_check.py`. Designed first (docs/VOICE.md), tested with fake audio. Live-checked by the owner on the real microphone; since then Whisper gets a vocabulary hint (`STEEL_VOICE_HINT`). Phase 5a switched off onnxruntime's telemetry, which faster-whisper's voice detection had been sending (docs/VOICE.md section 3). **Open:** Spanish and Italian accuracy (unmeasured), the effect of the hint (unmeasured), a lock for several processes. **Wake word and always-on listening: only the foreground `steel jarvis` loop** (5f below); nothing else, by design (docs/VOICE.md section 7).
5b. Done (Phase 3): one camera snapshot on demand, fully local: consent file, visible CAMERA OPEN line, `camera_look` tool behind `sensor:camera`, `steel vision check|consent|revoke`, `steel look [--save]`, `scripts/vision_check.py`. Designed first (docs/VISION.md), tested with a fake camera and a fake vision model. Live-checked by the owner on the real camera; since then the default model is `qwen3.5:2b` (about 25 s a look; `qwen2.5vl:3b` about 100 s). After the live check: a 20-frame warm-up and one retry for a black picture, and `steel look` waits for Enter. **Open:** how well either installed vision model describes a real room (not measured by a test). **Not implemented, by design: continuous video, always-on watching, motion detection, recognising or identifying people** (docs/VISION.md section 7).
5c. Done (Phase 4): slash commands in `steel chat` (`/search`, `/notes`, `/room`, `/look`), typed by the owner, run as agent `chat` through the policy; results are shown first and added to the conversation only on Enter, as data that never reaches memory; a separate `memory:read:room` capability and `memory_search_room` tool; `steel doctor` warns about memory pressure. Threat model and rules written first (docs/INJECTION.md). **The model still cannot run any tool.** Since Phase 5a room notes are not in the chat prompt (`/room` fetches them on demand). **Open:** a measured injection test suite against the real local model; per-person memory handling. **Not implemented, by design: model-initiated tool calls** (docs/INJECTION.md section 4 lists what must be true first).
5d. Done (Phase 5a; the roadmap's 5a is voice input): spoken replies, opt-in per session (`steel chat [--voice] --speak`), behind a new `audio:play` capability and the `speak` tool (agent `voice`); local Piper (GPL-3.0-or-later) as a separate program with no network (`unshare --net`), text on stdin, audio through pipes to `aplay`, a visible SPEAKING line, Enter or a typed line or Ctrl-C stops; never tool data, room notes, camera text or flagged text; `steel speak check|say`, `scripts/speak_setup.py` (pinned, hash-checked engine and voices), `scripts/speak_check.py`. Designed first (docs/SPEAK.md), tested with a fake engine and player; the real engine was run into memory only. Live-checked by the owner (reported 2026-10-25). **Open:** voice choice (British voices have unclear licences); the 4 s voice load (addressed in 5e); STEEL's own licence (Apache-2.0 since Phase 5b). Hands-free mode came in 5f (the Jarvis loop); **barge-in** (interrupting a reply by voice) is not implemented: it would need echo cancellation (docs/SPEAK.md section 7).
5e. Done in code (Phase 5b), **not yet measured live**: a faster turn (docs/LATENCY.md). `steel chat --timings` (numbers only); the model warmed up at start (fixed one-word request, local Ollama only); optional `STEEL_OLLAMA_KEEP_ALIVE`; the Piper engine started before the reply exists, so its voice is loaded in time (into memory: 0.37 s to first audio instead of 4.4 s), and killed with STEEL; **Phase 5b-2, done in code, not measured live:** one `num_ctx` (default 4096, `STEEL_OLLAMA_NUM_CTX`) on every request, history cut to fit, a warm-up that carries the first turn's prefix, and a Piper engine that stays loaded for the session with replies ended by silence (`STEEL_SPEAK_IDLE_END_SECONDS`); **Phase 5b-3, done in code, not measured live:** `--timings` shows the warm-up outcome, queueing and prompt token counts; the base prompt is 23 percent shorter; the last two voices stay loaded (`STEEL_SPEAK_KEEP_VOICES`, `STEEL_SPEAK_VOICE_IDLE_MINUTES`); the `engine:` label describes the engine's state. **Open:** why turn 1 still reads its whole prompt (a hybrid-model cache limit is suspected, docs/LATENCY.md section 10.2); `scripts/latency_check.py` for the owner; `LICENSE` (Apache-2.0) and `NOTICE`. **Not done:** streaming the reply and speaking while it is generated, because `GuardrailsEngine.stream` does not redact the output; using the integrated GPU (Ollama 0.40.3 seems to need `OLLAMA_IGPU_ENABLE`, an owner's setting).
5f. Done in code (Phase 5c), **not yet run live by the owner**: the Jarvis loop (docs/JARVIS.md), a hands-free wake word ("hey jarvis") in the foreground of a terminal only, after the owner lifted the wake-word rule for that design alone (2026-10-25). Designed and committed before any code; each docs/VOICE.md section 7 requirement met and tested: a separate always-on consent, a red window outside the terminal plus a terminal line before the microphone opens, `steel jarvis stop` and a watchdog that work while the loop is stuck, nothing kept before the trigger, a third-party review, and its own capability `sensor:microphone_always_on`. STEEL's own port of openWakeWord on onnxruntime (telemetry off first; 36 ms of CPU per second of audio on synthetic audio); request with a countdown; no tools by voice; not remembered unless `--remember-voice`; listening resumes only after the player exited plus 0.5 s. `steel jarvis check|consent|revoke|stop`, `scripts/wake_setup.py`, `scripts/jarvis_check.py`. Tested with fakes and stand-in processes only; a per-test time limit was added after an unfinished test froze the owner's computer. **Open:** the owner's live run (real "hey jarvis", false-trigger rate, the window on the real desktop); the model files are **non-commercial** (CC BY-NC-SA 4.0); a custom "hey steel" model; barge-in. **Not implemented, by design:** a background service, daemon or start at login; speaker recognition.
6. Mobile/API: authentication and authorization must come before any remote command interface.

These are planned milestones with no promised dates. The security module will be limited to owned or explicitly authorized environments.
